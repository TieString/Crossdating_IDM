# 缓存管理

入口：设置 → 缓存管理。显示临时缓存与文件工作区记录各自的文件数和占用空间。

- 临时缓存：官方 COFECHA 的 `cofecha-work` 文件、保存的报告、`tree-ring-scans-v1` 扫描影像副本。默认仅清理这些内容；之后按需重建，需保留原始 RWL 和扫描图片。
- 文件工作区记录：编辑草稿和操作历史、手动/动态参考配置、扫描标注。按 RWL 路径关联，重命名文件会使旧路径记录留存。勾选“同时清除所有文件工作区记录”并确认后才删除；请先保存需要保留的工作。磁盘 RWL 不会被写入或删除。
- 点击“下次启动时清理”后，退出软件的全部窗口，再重新启动。执行前可在同一设置页取消。清理结束后可在该页查看结果。

程序在主窗口挂载 React、启动 Worker、恢复草稿及迁移旧 localStorage 记录之前清理，避免运行中的文件锁和延迟写回。辅助窗口不执行清理。清理目录限定在应用数据目录下的 `cofecha-work`、应用缓存目录下的 `tree-ring-scans-v1` 及 `workspace-state-v1` 中可识别的记录文件。旧浏览器工作区缓存同步处理，软件设置和模型保留。符号链接及未知工作区文件跳过。

回收机制：官方 COFECHA 工作目录在执行前清理；扫描影像磁盘预算可在缓存管理中选择2/4/8/16/32/64/128 GiB，默认16 GiB，在下一次加载影像时采用。按最近使用时间淘汰副本，所有窗口正在读取的缓存文件都受保护；活动读取允许暂时超预算，读完后回收。窗口销毁时释放该窗口残留的读取保护。影像生成使用后台线程，完整写入后才成为可读缓存。按文件路径保存的工作区记录不自动过期，防止自动删除未保存工作。

内存Blob缓存的384 MiB/12项预算仍保留，但它是闲置回收预算；正在显示的影像即使超过预算也不会被回收。并发请求在加载前登记引用，切换工作区时使用中的旧影像在最后一次释放后才销毁。磁盘预算不等于解码内存上限；TIFF仍先显示小总览并按需提取原分辨率截面，不批量读取整个影像目录。

验证：缓存策略测试覆盖默认保留草稿、显式清理工作区、取消任务、旧路径缓存迁移和符号链接跳过；设置渲染测试覆盖默认未勾选和待清理范围。未对用户真实缓存执行清理。
