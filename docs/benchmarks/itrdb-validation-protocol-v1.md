# ITRDB JS 事件诊断验证协议 v1

本协议用于验证纯 TypeScript 事件级诊断在 ITRDB 上的站点外泛化能力。协议和
final 案例清单必须先提交，之后才允许运行 final；final 结果不得用于调参。

## 数据拆分

- 数据目录：`D:/软件测试/数据/ITRDB/itrdb_download/measurements`
- 拆分单位：完整 RWL 文件（站点），同一文件中的样芯不得跨集合。
- 路径先转为小写、正斜杠并移除开头斜杠，再计算 FNV-1a 32 位哈希。
- 哈希末位桶 `0-5` 为 development，`6-7` 为 calibration，`8-9` 为 final。
- 冻结清单为 `itrdb-validation-v1-manifest.json`，每个入选源文件记录 SHA-256。

## 纳入标准

- 随机注入样芯：至少 150 年、无原始 0、至少 5 条参考样芯重叠 80 年。
- 自然 0 样芯：至少 120 年、0 密度不超过 10%、至少 5 条参考样芯重叠 80 年。
- 注入年份只由文件路径、样芯编号、日历位置分层和固定 seed 决定。
- 选择阶段不读取相关系数、诊断得分、局部环宽大小或 COFECHA 结果。
- 旧端距离小于 14 年的自然 0 可保留为污染上下文，但不进入准确率分母。
- 新端只要求 2 年较新侧上下文，以保留此前要求的新端困难案例。

## 固定规模

每个集合包含：

| 场景 | 组数 | 每组操作 |
| --- | ---: | --- |
| 单事件随机注入 | 240 | 同一年分别注入缺轮、伪轮，并跑一个干净负例 |
| 原始自然 0 | 80 | 删除一个真实 0 |
| 多个离散缺轮 | 45 | 三个位置分层、间距至少 12 年，逐步真值辅助恢复 |
| 相邻缺轮 | 45 | 两个连续年份，逐步真值辅助恢复 |
| 不同样芯异年错误 | 35 | 两条样芯同时在不同年份缺轮 |
| 整站自然 0 自举 | 6 | 所有含 0 样芯同时删除全部 0，分别跑真值辅助与自动闭环 |

三个集合合计 1,353 个场景组。单事件部分产生 1,440 个事件案例和 720 个干净
负例；补充部分还会产生逐步案例，因此最终事件行数高于场景组数。

## 计量口径

- 响应率：系统是否输出唯一主建议，不要求类型正确。
- 操作准确率：唯一主建议的类型是否与真值一致。
- 主窗口覆盖率：类型正确且唯一主窗口包含真年份。
- 条件覆盖率：在主操作类型正确的案例中，主窗口覆盖真年份的比例。
- Top1：类型正确且窗口内首位年份等于真年份。
- 拒答率：未输出主建议。
- 局部移动误判率：缺轮或伪轮真值被主建议判为 `partialMove`。
- 干净误报率：未注入事件的目标样芯产生任意主建议。
- 窗口宽度同时报告中位数和 P90；错误操作产生的异常宽窗不会被隐藏。

分层至少包括数据目录组、序列长度、参考深度、缺轮数量、事件间距、端点距离、
原序列是否已有建议。局部信号强弱只允许在选定年份之后测量并用于事后分层。

## 可复现命令

```powershell
npm run benchmark:itrdb:prepare
npm run benchmark:itrdb:complex -- --split development --workers 6
npm run benchmark:itrdb:complex -- --split calibration --workers 6
# 参数和清单提交冻结后，最后运行：
npm run benchmark:itrdb:complex -- --split final --workers 6
```

`benchmark:itrdb:formal` 保留原 Vitest holdout 作为独立交叉核验；它使用同一站点
拆分和不看信号的年份选择，但不替代冻结清单主结果。
