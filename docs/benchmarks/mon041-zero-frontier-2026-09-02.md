## 复现的接入错误

修复前，单独删除任一0后，family头实际均把操作判为missing，但运行时无条件输出：

1. `whole -4`
2. `partial -6`
3. missing

因此首个UI建议既不是模型真正选择的操作，整体/局部位移也只是各自位移头的常见类别。单删5例和全删串行5步的首次建议均为 `0/5` 正确。

## 修复

- 删除固定 `whole → partial → unit` 解释链。
- 事件门通过后，family头在 `missing / false / partial / whole` 中选择唯一操作。
- family选择partial时，主建议保持partial；同时在同一冻结证据状态上运行missing定位器，生成一个单向“以缺轮形式复核”动作。
- 点击后切换为`missing −1`及missing定位器的唯一13年窗口，不复制partial窗口，也不重新运行family。
- missing切换在当前主事件ID下优先于图表焦点；应用missing并重建RWL状态后，新事件ID允许重新判断partial。
- UI事件不再附带 `sequentialOperationRecovery`，因此不会再出现与当前模型判断无关的“用局部移动解释/用缺轮解释”按钮链。
