# ITRDB 全零删除参考结构分层 v1

## 目的

“复杂文件”只表示：删除文件内全部自然 0 后，文件内部已经没有足够稳定、且明显胜出的相对参考结构。它不表示事件多，也不能依据算法恢复率事后定义。

分层仅用于全零删除压力测试的准确率统计，不进入生产诊断，不隐藏用户界面建议。共同缺年等绝对不可辨识事件仍先从绝对年份指标中单独排除。

## 冻结判定

只使用初始删零状态，满足任一路径即保留在主指标中：

1. 全局 zero-lag 最优比例不低于 35%。
2. 存在主导参考簇：覆盖至少 35% 序列，规模至少为第二大簇 3 倍，簇内有效边密度不低于 20%，簇内 zero-lag 最优比例不低于 25%。
3. 存在较小但高度一致的参考簇：覆盖至少 30% 序列，边密度不低于 60%，zero-lag 最优比例不低于 65%，绝对 lag P90 不超过 2 年。

恢复事件数、最终 zero-lag、最终 lag P90、文件名和已知失败案例均不参与判定。

## 20 文件冻结结果

保留主指标的 14 个文件：ca612、ca646、ca660、co589、co593、co604、co605、co612、co616、co617、co624、co631、co632、mt001。

参考结构丢失、单独报告的 6 个文件：az086、co021、co583、co647、co649、co651。

co612 虽有 358 个事件，初始全局 zero-lag 仅约 0.246、绝对 lag P90 为 7 年，但仍有 41/56 的唯一主导参考簇，因此必须保留在准确率指标中。az086 的最大簇只有 6/28，主簇优势不足，且 146 个事件绝对不可辨识，因此归入参考结构丢失压力集。
