# Unified adjudicator v2 workflow-package freeze

## Decision point

This document freezes the evaluation package before opening the 17-file final
holdout. Production diagnosis remains unchanged.

The automatic main suggestion is the existing zero-regression structured result.
The package may additionally contain one immutable, user-invoked review
interpretation generated by the enriched operation/location heads. It is not an
automatically applied replacement and is never displayed as a list of windows.

## Frozen evidence generator

- Operation identities: Top10 truth-blind operation identities plus product-package
  identities and the best identity of each local operation type.
- Shared yearly evidence: master counterfactual, raw and COFECHA-style lag
  transition, cumulative CUSUM, piecewise objective, reference change-point
  consensus, reference-wise lag transition, per-reference counterfactual, and
  partial boundary evidence.
- Candidate centers: fixed calendar stride 5 plus the unique peak of every evidence
  profile.
- Window: one 13-year window; no widening or alternative window list.
- Operation head: enriched operation classifier. Operation ranker weight is 0.
- Unit-event location: global/typed window classifier with weights 0.5/0.5.
- Partial-move location: global/typed transition ranker with weights 0.5/0.5.
- Automatic partial semantics remain negative and less than -1.

## Frozen metric

Workflow-package success means that either the safe main suggestion or its one
supported review interpretation has the correct workflow operation and a unique
window covering the current truth. Strict main-suggestion accuracy, response,
refusal, Clean false positives, and correct-to-incorrect changes remain separate
metrics and may not be hidden by the package metric.

The final acceptance target is applied independently to A, B, C, and D:

- workflow-package accuracy at least 95%;
- file-clustered one-sided 95% lower bound at least 90%.

## Automatic-selection boundary

The separately calibrated automatic package selector is not accepted: with the
correct main package protected, the four-family 95% constraints are infeasible on
replacement calibration. Application-residual evidence does not resolve that
boundary. The final holdout therefore validates the workflow package only; it does
not authorize automatic replacement or production integration.

No feature, weight, semantic policy, window rule, or threshold may be changed after
the final holdout starts.
