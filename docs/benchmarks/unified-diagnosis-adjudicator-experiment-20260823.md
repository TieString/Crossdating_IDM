# 统一事件裁决模型实验（2026-08-23）

## 结论

底层 lag、反事实和多参考芯证据尚未达到上限。当前产品管线在冻结样本上的工作流建议准确率为 92.91%，严格候选 Oracle 为 98.28%。将已有证据投影为不可变候选表，并使用结构化统一裁决模型后，文件级 OOF 准确率提高到 94.74%，且没有把任何原本正确的建议改错。

这验证了“统一证据表 + 单一结构化裁决器”方向，但本轮仍属于实验验证，尚未接入 Tauri 生产路径。

## 冻结数据与隔离

- 评估集：25 个完整 RWL 文件，500 个冻结案例。
- OOF 事件机会：931；Clean：100。
- 开发审计：2,152 次，来自已有冻结安全/错误审计运行。
- 外层与内层均按完整 RWL 文件分组；测试文件的评估和历史审计均从对应训练折剔除。
- 文件名、序列名、A/B/C/D 类别、注入年份和真值字段均不作为模型特征。
- Clean raw grid 几乎总能产生候选，因此拒答恢复单独要求内层错误事件恢复为 0、Clean 新误报为 0。

## 模型结构

统一候选表保留操作、位移、窗口、路径来源、反事实 gain、差分 gain、远峰 margin、联合位置支持和多路径投票等证据。最终裁决拆成三个受约束的头：

1. 操作/位移头只比较不同 `operationType x shiftYears`，不能移动同一操作身份的窗口。
2. 位置头只比较产品包内同一操作与位移的窗口，不能修改操作或位移。
3. 拒答头只处理原本无产品回答的案例，并使用零新增 Clean 误报的独立门槛。

主建议和已验证等价解释共同构成不可变产品包。任一头都不能重定位产品包内其他操作身份；最终仍只输出一个操作、一个位移和一个唯一窗口。

## 安全性

- 新修正 17 个原失败事件。
- 正确变错误：0。
- 原正确建议保持率：865/865 = 100%。
- 响应率：99.57%，仍拒答 4/931 个事件。
- Clean 误报：1/100，与产品基线相同；拒答头新增 Clean 误报为 0。
- 决策来源：产品 906、操作头 18、位置头 1、拒答恢复头 3；其余 103 包含 99 个 Clean 安全拒答和 4 个事件拒答。

## 负结果

- 将全部历史开发审计同时用于门槛校准后，模型过度保守并降至 871/931；该方案不采用。
- LambdaRank 在 37 个存在不同操作身份正确候选的产品失败中 Top1 为 27/37（72.97%），与现有 pair 模型相同。两者各自独有 4 个正确 Top1，但本轮没有足够独立校准证据安全合并，因此不接入最佳模型。
- 继续增加 raw 字段本身没有突破：增强证据字段后，单头 pairwise 仍只修正 4 个案例。关键提升来自权限拆分、产品包语义和风险校准，而非单纯扩大树模型。

## 剩余边界

统一模型仍有 49 个错误或拒答事件：

| Oracle 状态 | 数量 |
| --- | ---: |
| 已有严格完整候选 | 35 |
| 已有工作流等价完整候选 | 6 |
| 操作和位置分别存在 | 3 |
| 只有操作证据 | 4 |
| 没有完整证据 | 1 |

对应原管线损失主要为 evidence projection 22、no complete hypothesis 9、joint selection 8。下一次提升应优先研究候选概率校准和 pair/ranker 分歧的独立校准集，而不是继续添加操作特例。
