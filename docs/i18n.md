# 中文 / English language switching

## 使用 / Usage

选择“文件 → 设置 → 语言 → English”；英文界面路径为 “File → Settings → Language”。默认继续使用简体中文。无需重启，也不会刷新/重新挂载工作区；可随时切回。语言偏好单独持久化，旧版设置无需迁移。

Choose **File → Settings → Language**. The default remains Simplified Chinese. The preference applies immediately and is restored when the application starts again. Switching does not reopen the current file or reset the editor.

## Scope and data boundaries

- The offline catalog covers the application's menus, settings, dialogs, tooltips, accessibility labels, diagnostic explanations, operation-log descriptions, scan-image controls, report navigation and effective-change CSV headings/descriptions.
- Series IDs, filenames/paths, raw text editor contents, numbers, years, signed shifts, model outputs and COFECHA OUT report bytes are not translated. The CSV is localized only at export; its source history remains unchanged. Technical operation codes remain stable.
- Existing app-generated diagnostic/error messages are matched against complete catalog templates at display boundaries. Unknown third-party/native error details are intentionally preserved, not guessed or passed to an online translator. Native file-picker system buttons follow the operating-system locale. “简体中文” remains the language's self-name in the English selector.
- This is runtime interface localization, not a translation of source comments, benchmark documents, licenses, or repository history.

## Implementation

`src/i18n/core.ts` owns the typed `zh-CN | en-US` store and offline message lookup. Preference key: `crossdating-idm-language`. It is independent of the settings object and RWL workspace snapshots. Invalid/blocked preferences fall back to Chinese. A failed preference write still changes the live interface and reports that persistence failed.

`src/i18n/react.tsx` provides a `useSyncExternalStore` subscription and one `LanguageBridge` per webview. It receives both same-origin storage events and Tauri `crossdating-idm://language` events without rebroadcast loops. Async native listeners are cleaned up even during React StrictMode's setup/cleanup cycle. Native titles are updated at the window boundary; an open file's name is preserved.

`src/i18n/en.json` maps normalized Chinese source messages to English with numbered placeholders. `t()` interpolates once; inserted parameters are not recursively translated or interpreted as replacement patterns. JSX boundary whitespace is retained. `localizeMessage()` is a complete-message adapter for canonical app-generated records, not a substring or DOM translator. `operationLog.ts` uses typed operations to distinguish labels from identifiers, including a series literally named “左侧”.

Only language-sensitive memoized text is invalidated by locale changes. The editor, selection, scan state, chart plugins, model and numeric computations do not acquire language-dependent identity. The settings window is resizable with additional space and wrapping for English labels.

## Adding a message

1. Use `t("中文文案 {0}", [value])` at the display boundary and add the English entry with the same placeholder indexes. Keep identifiers and external text in parameters.
2. Subscribe a React component with `useLocale()`; include locale in a memo/effect only when it produces localized text. Never put Hooks in lazy-loading callbacks.
3. For errors/history created in domain or worker code, keep the canonical record and localize at rendering/export. Add a typed adapter where a record mixes labels and user identifiers.
4. Run `npm run build`, `npm run test:production` and `npm run test:i18n`.

No new runtime dependencies or external translation services are required.

## Validation and desktop acceptance

The i18n suites check preference fallback/persistence/subscription cleanup, complete catalog entries and placeholder parity, Chinese-literal coverage in runtime React views, English and Chinese diagnostic rendering, preservation of embedded IDs and paths, compound CSV notes, repeated switching of a real RwlEditor with undo/redo, and the frozen model's exact SHA-256.

A local Chromium interaction check with mocked Tauri IPC exercised all settings sections, English-to-Chinese switching, storage-event synchronization, preservation of Chinese find/replace input, the empty main view, context menu and diagnosis panel. No application-owned Chinese labels remained in those English views; the deliberate language self-name is excluded. This check is not a native Tauri or end-to-end COFECHA execution test.

Before publishing a desktop release, check on the target Windows/macOS/Linux build: reopen the app to verify persistence; keep settings, chart, log and COFECHA windows open and switch in either direction; check native titles and dialog labels; edit and undo a real RWL in both languages; confirm original OUT exports are byte-identical. Native desktop interaction and installer packaging are separate release checks, not implied by the frontend tests.
