# RWL来源单位显示修复验收

## 修复结果

应用保留0.001 mm内部工作数据，显示层使用独立的、按段计算的单位信息。显示与序列化复用同一个来源精度判断函数，避免两个出口各自推断单位。

| 场景 | 显示/输入 | 内部数值 | 保存文本 |
| --- | --- | --- | --- |
| 999来源段，原值706 | 706，0.01 mm | 7060 | 706 |
| 修改上述值为707 | 707，0.01 mm | 7070 | 707 |
| −9999来源段，原值706 | 706，0.001 mm | 706 | 706 |
| 999来源段中的真实999 | 可编辑的999 | 9990 | 测量999，另有段结束符 |

显示转换覆盖宽度格、编辑输入、数字动画、删除标记、查找替换、年/值文本编辑、控制台复制、操作日志和有效修改CSV的单值记录。宽度格及序列标题显示单位。图表只转换刻度标签和提示框，不修改曲线计算坐标、参考序列或诊断证据；独立图表/日志窗口接收相同单位信息。

当缓存与磁盘工作数值完全一致但来源精度不同，当前显示采用磁盘精度，保留缓存的原始基线、日志和标记，并持久化修正后的显示元数据。缓存数据与磁盘不同仍走原有选择流程。

- 生产测试205/205通过，已加入显示单位和查找替换回归。
- 实文件测试使用桌面`BL11 - 副本.rwl`，逐个核对原始测量值与显示值，并核对文件字节未变；其SHA-256为`ba542d8198c650e65e651dfb13d797902e2c2abecadaa739c312da52503b4cf7`。
- TypeScript严格检查及`npm run build`通过。Vite仍有已有的大chunk和静态/动态混合导入提示。
- 浏览器加载实际WidthGrid、RwlEditor及显示上下文：确认706/815/999显示、双击706输入707、内部7070、撤销回706、恢复回707、内存序列化再解析后仍显示707。粗精度结束符显示999，细精度结束符显示−9999。
- 浏览器另测707.1细精度输入，内部仅转换为7071一次；该段提升到0.001 mm后显示7071，撤销恢复原0.01 mm显示。
- 自动测试覆盖同名混合精度段、插年与整体移动、旧缓存精度恢复、完整日志和基线保留、工作区导入及重开。
