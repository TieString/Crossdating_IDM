## 两种分母

`workflowSuggestionAccuracy` 沿用原口径：首次人工介入前，正确完整建议数 / 实际发生的前沿诊断数。
后期未到达事件不进入分母。

`humanAssistedFullEventSuggestionAccuracy` 是本轮新增主参数：当前事件失败时只把该事件记为失败，
随后模拟用户正确解决当前阻塞，重新构建 RWL、COFECHA、参考和诊断，使每个真值事件都获得一次
独立建议机会。人工解决不进入正确建议分子。

## 受阻计失败全事件准确率

这个指标以每类全部真值事件为分母。一个当前事件失败后，该事件以及尚未轮到的所有后期事件
均计为错误，不使用人工救援解锁后的结果。它与原字段 `serialRecoveryRate` 数值相同，但这里按
“全事件准确率”明确报告：

| 类别 | 正确事件/全部事件 | 受阻计失败全事件准确率 |
|---|---:|---:|
| A | 945/1000 | 94.50% |
| B | 2442/3001 | 81.37% |
| C | 2475/3003 | 82.42% |
| D | 1918/2536 | 75.63% |
| 合计 | 7780/9540 | 81.55% |

因此，原前沿准确率 90.94% 不能代表全部事件；当所有被阻塞事件也计错时，总体准确率为
81.55%。人工解阻后全事件准确率 89.92% 则回答另一个问题：后期事件真正获得机会后，算法能
正确建议多少。

## 传递式解释

本轮新增以下受约束解释链：

```text
wholeSeriesMove -> missingRing | falseRing | partialMove
partialMove -> missingRing
wholeSeriesMove -> partialMove -> missingRing
```

共 15 次建议通过传递式复核成为正确完整建议，全部发生在 C 类多缺轮案例：

- 10 次 `partialMove -> missingRing`
- 5 次 `wholeSeriesMove -> partialMove -> missingRing`

它们只占全部 9540 个事件的 0.16%，因此总体提升并非由宽松等价口径主导。每次仍要求最终
missingRing 操作语义正确且唯一窗口覆盖真年份。

## 结论

1. 原前沿口径总体已经超过 90%，但它仍会遗漏被阻塞的后期事件。
2. 人工解阻后的全事件口径为 89.92%，证实阻塞带来的乐观偏差约为 1.02 个百分点。
3. A 达到观察值和聚类下界双重 90% 门槛；C 只达到观察值；B 和 D 尚未达到观察值。
4. D 的主要操作仲裁修复有效，全事件准确率较上一轮提高 7.73 个百分点。
5. 当前主要短板转为 B 的多个 partialMove、C 的 gap5 多缺轮，以及四类型 D 混合事件。
