/goal
在当前 Crossdating_Tauri 项目中完整实现“COFECHA-like Bayesian Segment Lag Path 优化版自动交叉定年建议系统”，重点提升缺轮 insertMissingYear 和伪轮 deleteFalseYear 的识别准确率。目标不是重写现有算法，而是在现有诊断流程上增加一层更强的段级年代状态推断和候选扩展机制。

当前结果：

* 缺轮 top1 ≈ 0.50
* 伪轮 top1 ≈ 0.33
* 缺轮 top5 ≈ 0.58
* 伪轮 top5 ≈ 0.58
* 整条移动 top1 ≈ 0.88
* clean 假阳性 = 0.00

优化目标：

* 第一阶段：缺轮 top5 ≥ 0.85，伪轮 top5 ≥ 0.80
* 第二阶段：缺轮 top1 ≥ 0.75，伪轮 top1 ≥ 0.65
* 最终目标：缺轮和伪轮 top1 尽量接近或超过 0.80
* clean 强假阳性保持 ≤ 0.20，优先保持当前 0.00 的保守性

不要只调评分权重。当前最大问题是候选召回不足，真实位置经常没有进入 top5。必须优先增强候选生成和边界识别能力。

二、多尺度 COFECHA-like segment lag table
────────────────────────

当前 segments.ts 只输出 r0 / bestLag / bestR 等摘要。需要新增完整 lag table。

新增类型：

type SegmentLagCorrelation = {
lag: number
r: number
tLike: number
effectiveN: number
fisherZ: number
}

type SegmentLagTableRow = {
scale: number
step: number
startYear: number
endYear: number
centerYear: number
effectiveNAtLag0: number

correlations: SegmentLagCorrelation[]

bestLag: number
bestR: number
bestT: number

r0: number
t0: number

rImprovement: number
tImprovement: number

posteriorByLag?: Record<number, number>
entropy?: number
confidence?: number
}

type MultiScaleSegmentLagTable = {
targetId: string
rows: SegmentLagTableRow[]
lagRange: [number, number]
scales: number[]
}

实现函数：

computeSegmentLagTable(input, params): MultiScaleSegmentLagTable

默认参数：

* lagRange = [-10, +10]
* scales = [30, 50, 70]
* stepByScale:

  * 30 → 10
  * 50 → 10 或 25，优先 10 提高边界分辨率
  * 70 → 15 或 25
* minEffectiveN:

  * scale 30 → 12
  * scale 50 → 20
  * scale 70 → 30
* 保留当前 50/25 行为作为兼容模式，但新增 multi-scale 模式作为默认优化路径

每个 segment 必须计算 lag -10 到 +10 的完整 correlation table，不再只取 bestLag。

lag 定义必须保持项目当前约定：
target[year] ↔ master[year + lag]

解释：

* lag < 0：较老侧可能缺轮，候选 insertMissingYear
* lag > 0：较老侧可能多轮 / 伪轮，候选 deleteFalseYear

必须处理：

* NaN
* 0 宽度值保留，但标准化函数决定如何处理
* effectiveN 不足时该 lag 不参与
* 方差为 0 时 r = NaN，不能崩溃
* lag 表要可用于 UI/调试输出

────────────────────────
三、lag correlations → likelihood / posterior
────────────────────────

新增模块 segmentLagLikelihood.ts。

目标：
把每个 segment 的 lag correlations 转成每个 lag 的概率质量，而不是硬 bestLag。

新增类型：

type SegmentLagLikelihoodRow = SegmentLagTableRow & {
likelihoodByLag: Record<number, number>
posteriorByLag: Record<number, number>
bestLagPosterior: number
lagEntropy: number
lagConcentration: number
}

实现函数：

convertLagTableToLikelihood(table, params): SegmentLagLikelihoodRow[]

建议方法：

1. 对每个 lag 的 r / tLike 构造 score：
   lagScore =
   wR * fisherZ(r) * sqrt(max(effectiveN - 3, 1))

   * wT * tLike
   * wImprovement * max(0, r - r0)

   - invalidPenalty

2. softmax 转 posteriorByLag：
   posteriorByLag[k] = exp(score[k] / temperature) / sum(exp(score / temperature))

3. 默认 temperature = 0.35–0.60，需要可配置。

4. 如果 bestR 和 secondBestR 差距很小，posterior 分布应更平。

5. 如果 effectiveN 小，posterior 应更平。

6. lagEntropy 高表示该 segment 不确定，后续 HMM 中权重降低。

7. lagConcentration = max(posteriorByLag)。

默认权重：

* wR = 1.0
* wT = 0.15
* wImprovement = 1.5
* minPosteriorFloor = 1e-6

输出要求：
每个 segment row 必须保留：

* posteriorByLag
* bestLagPosterior
* entropy
* confidence

────────────────────────
四、Bayesian / HMM lag path inference
────────────────────────

新增模块 bayesianLagPath.ts。

目标：
将多个 segment 的 lag posterior 作为观测，推断整条序列沿时间方向的隐藏累计 offset 状态路径。

窗口按时间从新到老排序，因为当前编辑规则固定 endYear：

newer → older

隐藏状态：

S_t = segment t 的累计 lag / offset 状态

允许状态：

* minState = -maxState
* maxState = +maxState
  默认 maxState = 3

新增类型：

type LagPathState = {
segmentIndex: number
centerYear: number
stateLag: number
logPosterior: number
observationLogLikelihood: number
}

type LagTransition = {
fromLag: number
toLag: number
delta: number
kind: "none" | "insertMissingYear" | "deleteFalseYear" | "multiYearMove"
boundaryYearEstimate: number
logProbability: number
}

type BayesianLagPathResult = {
targetId: string
mapPath: LagPathState[]
transitions: LagTransition[]
pathLogPosterior: number
boundaryPosteriors: BoundaryPosterior[]
wholeSeriesLagPosterior: Record<number, number>
diagnostics: {
segmentCount: number
stateRange: [number, number]
averageLagEntropy: number
averageLagConcentration: number
}
}

HMM 观测似然：
P(observation_t | S_t = k) = segmentPosteriorByLag[k]
使用 log probability。

转移先验：

* no change: 高概率
* stateLag 变化 ±1：低概率，代表单个 insert/delete 边界
* stateLag 变化绝对值 > 1：强惩罚，只有 whole/partial move 场景才允许
* 短距离连续反向变化强惩罚
* 编辑次数越多，先验越低

默认转移 log prior：

* stay same: log(0.96)
* +1 / -1 transition: log(0.02)
* abs(delta) > 1: log(0.002)
* reverse transition within 30 years: additional penalty
* too many transitions: penalty

实现：

* Viterbi：输出 MAP lag path
* Forward-backward：输出每个 boundary 的 transition posterior

必须实现 forward-backward，不只 Viterbi。因为候选生成需要边界 posterior，不只是单条最优路径。

边界定义：
相邻 segment t 和 t+1 之间的年份范围。
boundaryYearEstimate 可取两个 segment centerYear 的中点，也可根据重叠窗口边界计算更合理位置。

transition 解释：
从新到老：

* 0 → -1：insertMissingYear 边界
* 0 → +1：deleteFalseYear 边界
* state 整体非 0 且无明显 transition：wholeSeriesMove
* 某个边界前后长期不同 state：partialRangeMove

必须输出：

* boundaryPosteriors: 每个边界上 insert / delete / no-change / move 的概率
* wholeSeriesLagPosterior: 整条移动可能性

────────────────────────
五、boundary posterior 生成候选
────────────────────────

新增模块 boundaryPosterior.ts。

类型：

type BoundaryPosterior = {
boundaryYear: number
insertPosterior: number
deletePosterior: number
noChangePosterior: number
movePosterior: number
dominantTransition: "insertMissingYear" | "deleteFalseYear" | "none" | "move"
confidence: number
supportingSegments: SegmentLagLikelihoodRow[]
}

从 HMM forward-backward 中提取：

* P(S_t - S_{t-1} = -1) → insertPosterior
* P(S_t - S_{t-1} = +1) → deletePosterior
* P(S_t = S_{t-1}) → noChangePosterior

注意项目 lag 符号：
如果实现方向是 newer → older：

* transition delta = -1 对应 insertMissingYear
* transition delta = +1 对应 deleteFalseYear

必须写单元测试防止符号反转。

边界筛选：

* insertPosterior >= 0.15 进入 insert 候选扩展
* deletePosterior >= 0.15 进入 delete 候选扩展
* 如果 posterior 不高但 COFECHA hints 很强，仍进入 recall expansion
* 每条 target 最多保留 top 10 insert boundaries + top 10 delete boundaries

六、候选召回扩展 candidateRecallExpansion
────────────────────────

新增模块 candidateRecallExpansion.ts。

目标：
把 top5 recall 从 0.58 提高到 0.85+。宁可多生成候选，也不要漏掉真值。后续 evaluation 会淘汰错误候选。

候选来源必须包含：

1. HMM boundary posterior peak
2. boundary ± 10 年全枚举
3. COFECHA [A] 支持的 segment 边界
4. COFECHA [B] effect-on-correlation 年份
5. COFECHA [C] year-to-year divergence 年份对
6. COFECHA [E] outlier 年份
7. master strong narrow 年份
8. target local anomaly 年份
9. localEditAlignment top peaks
10. 当前 propagation boundary 旧逻辑候选

类型：

type RecallExpandedCandidate = {
type: "insertMissingYear" | "deleteFalseYear"
year: number
sourceEvidence: {
hmmBoundaryPosterior?: number
cofechaSegmentSupport?: number
cofechaEffectEvidence?: number
cofechaYearToYearEvidence?: number
cofechaOutlierEvidence?: number
masterNarrowEvidence?: number
targetAnomalyEvidence?: number
localEditAlignmentEvidence?: number
propagationBoundaryEvidence?: number
}
sourceTags: string[]
preliminaryScore: number
}

规则：

* 对每个高 posterior boundary，枚举 boundaryYear ± 10 年。
* 如果 top5 recall 仍不足，将范围扩大到 ±15 年。
* 每种类型最多保留 30 个候选进入 evaluation。
* 优先保留多证据重合的年份。
* 不能只保留 3 个候选年。
* insert 和 delete 分开保留。
* 不要在 recall 阶段过度过滤。
* clean 数据中候选多没关系，只要 evaluation 不给强分。

insert 候选加分：

* boundary insertPosterior 高
* master 在该年较窄 / 低 signal
* COFECHA [C] 年际突变 pair 包含该年或相邻年
* COFECHA [E] outlier 包含该年
* 插入 0 后初步局部 r 改善

delete 候选加分：

* boundary deletePosterior 高
* target 该年附近存在局部异常
* 删除后初步 local lag 回 0
* COFECHA [B]/[C] 年份附近有提示
* 不要求被删值极端小

七、真实编辑后 rerank
────────────────────────

保留当前 evaluation.ts 的核心设计：
每个候选都必须临时执行真实编辑，再重新完整诊断。

需要扩展评分输入，加入 HMM / COFECHA evidence。

新增类型：

type CandidateBayesianEvidence = {
hmmBoundaryPosterior: number
hmmPathSupport: number
segmentLagLikelihoodGain: number
cofechaHintEvidence: number
recallSourceCount: number
}

type CandidateRerankInput = {
candidate: RecallExpandedCandidate
evaluationDelta: CandidateEvaluationDelta
bayesianEvidence: CandidateBayesianEvidence
}

新增 candidateReranker.ts：

score =
4.0 * counterfactualImprovementScore

* 3.0 * hmmBoundaryPosteriorScore
* 2.5 * propagationResolutionScore
* 2.0 * lagRecoveryScore
* 1.5 * wholeSeriesImprovementScore
* 1.2 * segmentLagLikelihoodGain
* 1.0 * localBoundaryImprovementScore
* 0.8 * localGlkImprovementScore
* 0.8 * cofechaHintEvidence
* 0.6 * recallSourceCountScore
* 0.6 * narrowOrAnomalyEvidence

- 1.2 * newProblemPenalty
- 0.8 * editCountPenalty
- 0.4 * distanceFromBoundaryPenalty

Hard gate 仍然保留：
候选必须满足至少 3 项：

1. meanSegmentRAfter > meanSegmentRBefore
2. bLikeCountAfter < bLikeCountBefore
3. propagationResolved 或 propagationWeakened
4. lagRecoveryScore > 0
5. wholeSeriesRAfter >= wholeSeriesRBefore - 0.02
6. localBoundaryRDelta > 0
7. 没有 introducedNewStrongProblem

但增加召回保护：
如果 hmmBoundaryPosterior 很高且 counterfactual 不明显变差，可以保留为 low-confidence candidate，而不是直接丢弃。这样用于 top5 recall。
规则：

* strong candidate：hard gate passed
* weak candidate：HMM posterior 高，但 hard gate 不足；仅进入 top5/ambiguous，不允许自动推荐
* rejected candidate：真实编辑后明显变差

输出字段：
type CandidateStrength = "strong" | "weak" | "rejected"

UI 中：

* strong 才显示为正式建议
* weak 显示为“备选检查点”
* rejected 不显示或只在 debug 模式显示

八、COFECHA hints 深度融合
────────────────────────

已有 cofechaHints.ts 需要扩展。

解析：
[A] Segment lag table
[B] effect on correlation
[C] year-to-year changes diverging
[E] outliers

COFECHA [A] 用于：

* 增强 segment lag likelihood
* 校验 multi-scale lag table
* 增强 HMM boundary posterior
* 如果项目自身 lag table 与 COFECHA [A] 接近，confidence 增加

COFECHA [B]/[C]/[E] 用于：

* candidateRecallExpansion 年份候选扩展
* candidateReranker 中 cofechaHintEvidence 加分
* 不作为硬裁决

实现函数：

mergeInternalAndCofechaSegmentEvidence(internalTable, cofechaHints)

规则：

* 如果同一 segment 年份范围接近，且 highLag 与 internal bestLag 同号，则提高该 segment confidence。
* 如果 COFECHA highLag 与 internal bestLag 冲突，则保留两者，但降低该 segment certainty。
* 不能让 COFECHA 文本成为必需输入。

getCofechaEvidenceForCandidate(hints, candidate):

* 对 [B] 年份匹配 candidate.year ± 1 加分
* 对 [C] pair 包含 candidate.year 或边界 year 加分
* 对 [E] outlier candidate.year ± 1 加分
* 多段重复出现同一年，证据增强
* 返回 0–1 归一化 evidence

────────────────────────
九、多尺度 segment evidence 与 HMM 的关系
────────────────────────

多尺度 rows 可能高度重叠，不能简单当作完全独立观测，否则会过度自信。

处理方式：

1. 每个 scale 单独跑 HMM，得到 boundary posterior。
2. 再融合不同 scale 的 boundary posterior。
   或：
3. 在同一个 HMM 中给重叠窗口降权。

优先实现简单稳健方案：

* scale 30、50、70 分别构建 lag likelihood rows
* 分别运行 HMM
* 将三个 scale 的 boundary posterior 按权重融合

默认 scale weights：

* 30: 0.8
* 50: 1.0
* 70: 0.9

融合方式：
for each year:
fusedInsertPosterior = weighted average of nearby boundary insert posterior within ±5 years
fusedDeletePosterior = weighted average of nearby boundary delete posterior within ±5 years

输出 MultiScaleBoundaryPosterior：

type MultiScaleBoundaryPosterior = {
year: number
insertPosterior: number
deletePosterior: number
supportScales: number[]
scalePosteriors: Record<number, BoundaryPosterior>
confidence: number
}

如果多个尺度在同一边界 ±5 年内支持同一类型，则 confidence 增加。
