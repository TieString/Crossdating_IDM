工作序列

────────────────────────
二、改进 1：传播模式用 dominantLag，不要求 bestLag 完全相同
────────────────────────

当前逻辑：
segments.ts 会把相邻、具有相同 bestLag 的 B-like 窗口合并成 propagation pattern。

需要修改为：
相邻 B-like 窗口只要 bestLag 同号、绝对值接近、且 dominantLag 清晰，就可以合并成同一个 propagation pattern。

新增或修改类型：

type LagPropagationPattern = {
kind:
| "possibleMissingYear"
| "possibleFalseYear"
| "possibleWholeSeriesMove"
| "possiblePartialRangeMove"

dominantLag: number
lagConsistency: number
lagVotes: Record<number, number>

segments: SegmentDiagnosis[]
startYear: number
endYear: number

affectedSide: "older" | "newer" | "whole"
fixedSide: "newer"

confidence: number
}

合并规则：

1. 只合并 B-like segment。
2. 相邻或重叠窗口可以合并。
3. bestLag 同号即可进入同一个候选 group。
4. 允许轻微抖动，例如：
   [-1, -1, -2, -1] 应合并为 dominantLag = -1。
   [+1, +1, +2, +1] 应合并为 dominantLag = +1。
5. dominantLag 用绝对票数最多的 lag。
6. lagConsistency = dominantLag 出现次数 / group segment 数量。
7. lagConsistency 过低时降低 confidence，但不要直接丢弃。
8. 至少连续两个 B-like 窗口才形成 propagation pattern。
9. 如果 bestLag 正负号混杂，不形成单一 missing/false pattern，应标记为 ambiguous 或不输出单年插删建议。

分类规则：

dominantLag = -1：
→ possibleMissingYear

dominantLag = +1：
→ possibleFalseYear

abs(dominantLag) > 1 且影响大部分序列：
→ possibleWholeSeriesMove

只在较老一侧异常、较新一侧正常：
→ possiblePartialRangeMove

必须保持当前项目 lag 定义不变：
target[year] ↔ master[year + lag]

并且所有解释必须明确：
lag < 0 表示 target 需要向较老方向补缺轮，也就是候选 insertMissingYear。
lag > 0 表示 target 存在多余轮，也就是候选 deleteFalseYear。

注意固定末端年份规则：
当 endYear 固定时，在某一年插入缺轮 0，会导致该年以前的 target 年份整体前移，较新的年份不动。
这条规则必须写入代码注释和单元测试，防止 off-by-one 错误。

────────────────────────
三、改进 2：A-like / B-like 阈值按 effectiveN 和 tLike 自适应
────────────────────────

当前规则：
窗口长度 50
重叠 25
lag 搜索 -10…+10
至少 8 个有效年份对
当前相关阈值 0.32
bestLag 改善至少 0.08

问题：
8 个有效年份和 50 个有效年份的 r 可靠性不同。固定 r 阈值会导致小样本窗口假阳性。

需要实现：

每个 segment diagnosis 必须包含：

type SegmentDiagnosis = {
startYear: number
endYear: number
effectiveN: number

r0: number
bestLag: number
bestR: number
rImprovement: number

t0: number
bestT: number
tImprovement: number

fisherZ0: number
fisherZBest: number
fisherZImprovement: number

classification: "A_like" | "B_like" | "none"
confidence: number
}

新增工具函数：

pearsonR(x, y)
tLikeFromR(r, n)
fisherZ(r)
adaptiveLowCorrelationThreshold(n)
adaptiveImprovementThreshold(n)
classifySegment(segment, params)

tLike 公式：

t = r * sqrt((n - 2) / (1 - r * r))

需要处理：
n <= 2
r 接近 ±1
标准差为 0
NaN / Infinity

建议默认阈值逻辑：

if effectiveN < 8:
classification = "none"
confidence = 0

低相关阈值：
effectiveN >= 40: lowRThreshold = 0.32
effectiveN 25–39: lowRThreshold = 0.36
effectiveN 15–24: lowRThreshold = 0.42
effectiveN 8–14: lowRThreshold = 0.50

改善阈值：
effectiveN >= 40: minRImprovement = 0.08
effectiveN 25–39: minRImprovement = 0.10
effectiveN 15–24: minRImprovement = 0.14
effectiveN 8–14: minRImprovement = 0.18

B-like 判定必须同时满足：

1. bestLag != 0
2. rImprovement >= adaptive minRImprovement
3. bestT - t0 有明显提高，默认至少 0.6
4. bestR 达到最低可接受值，默认至少 0.25
5. effectiveN >= minValidYears

A-like 判定：

1. r0 < adaptive lowRThreshold
2. bestLag 没有显著改善，或 bestR 仍然低
3. 说明序列异常，但不一定是年份错位

none：
其余情况。

输出 confidence：
综合 effectiveN、rImprovement、tImprovement、bestR。

不要删除原来的 r0 / bestLag / bestR 字段。新增字段必须向后兼容 UI。

────────────────────────
四、改进 3：deleteFalseYear 候选必须通过传播恢复验证
────────────────────────

当前 deleteFalseYear 候选逻辑偏依赖：
局部相关
类似 COFECHA PART 6 [C] 的极端年际变化
与传播边界距离

需要增强：

deleteFalseYear 候选生成时仍可使用：

* propagation boundary 附近年份
* year-to-year change anomaly
* COFECHA-like [B] effect-on-correlation hint
* COFECHA-like [C] year-to-year divergence hint
* 局部相关改善

但这些只能作为候选生成或加分证据，不能作为最终裁决。

真正保留 deleteFalseYear 的条件必须来自 evaluation.ts 的临时删除后重新诊断结果：

delete candidate 必须检查：

1. 删除后 B-like segment 数量是否减少。
2. 删除后 dominant propagation 是否消失或减弱。
3. 删除后 affected older side 的 bestLag 是否更接近 0。
4. 删除后 whole-series r 不下降，或下降幅度低于可接受阈值。
5. 删除后没有新增更强 propagation pattern。
6. 删除后边界附近 local correlation 提升。
7. 删除后局部 slope / GLK 与 master 更一致。

新增或复用局部斜率一致率：

GLK-like:
对窗口内相邻年份变化符号做比较：
sign(target[y+1] - target[y]) == sign(master[y+1] - master[y])
计算一致比例。

delete 候选评分证据结构：

type DeleteFalseYearEvidence = {
candidateYear: number
boundaryDistance: number

beforeBLikeCount: number
afterBLikeCount: number
bLikeResolvedCount: number

beforeDominantLag: number | null
afterDominantLag: number | null
lagMovedTowardZero: boolean

beforeWholeSeriesR: number
afterWholeSeriesR: number

beforeLocalR: number
afterLocalR: number

beforeLocalGlk: number
afterLocalGlk: number

yearToYearChangeEvidence: number
cofechaHintEvidence: number

introducedNewPropagation: boolean
}

删除候选不能因为被删除值不是极小值就被丢弃。伪轮可能表现为：

* 一个正常年被分成两个偏小值
* 一个局部边界被误量成两轮
* 一个普通值导致后续年份整体错位

因此 delete 候选的核心判断是“删除后年份对应关系是否恢复”，不是“被删值是否极端”。

────────────────────────
五、改进 4：evaluation 增加硬门槛，降低局部窗口质量权重
────────────────────────

当前 scoring 中，单年插删的“局部窗口质量 = 编辑后局部相关 × 21”，权重过高，会让局部拟合支配排序。

需要修改 evaluation.ts：

先加 hard gate，再计算 score。

每个候选临时应用编辑并重新完整诊断后，计算：

type CandidateEvaluationDelta = {
meanSegmentRBefore: number
meanSegmentRAfter: number
meanSegmentRDelta: number

bLikeCountBefore: number
bLikeCountAfter: number
bLikeResolvedCount: number

aLikeCountBefore: number
aLikeCountAfter: number

propagationCountBefore: number
propagationCountAfter: number
propagationResolved: boolean
propagationWeakened: boolean

dominantLagBefore: number | null
dominantLagAfter: number | null
lagRecoveryScore: number

wholeSeriesRBefore: number
wholeSeriesRAfter: number
wholeSeriesRDelta: number

localBoundaryRBefore: number | null
localBoundaryRAfter: number | null
localBoundaryRDelta: number | null

localGlkBefore: number | null
localGlkAfter: number | null
localGlkDelta: number | null

introducedNewStrongProblem: boolean
}

Hard gate：
候选必须满足至少 3 项，才允许进入最终排序：

1. meanSegmentRAfter > meanSegmentRBefore
2. bLikeCountAfter < bLikeCountBefore
3. propagationResolved 或 propagationWeakened
4. lagRecoveryScore > 0
5. wholeSeriesRAfter >= wholeSeriesRBefore - 0.02
6. localBoundaryRDelta > 0
7. 没有 introducedNewStrongProblem

如果候选只满足局部相关提升，但 B-like 没减少、传播没改善、整体 r 下降，则丢弃。

新评分公式：

score =
6.0 * normalizedSegmentImprovement

* 3.0 * propagationResolutionScore
* 2.5 * lagRecoveryScore
* 2.0 * wholeSeriesImprovementScore
* 1.5 * localBoundaryImprovementScore
* 1.0 * localGlkImprovementScore
* 0.8 * narrowRingEvidence
* 0.8 * cofechaHintEvidence

- 1.2 * newProblemPenalty
- 0.8 * editCountPenalty
- 0.4 * distanceFromBoundaryPenalty
- 0.3 * rangeMoveDistancePenalty

局部窗口质量不再乘以 21。
localBoundaryImprovementScore 只有在 hard gate 通过后才参与评分。
如果 hard gate 未通过，局部窗口再高也不能保留候选。

候选 explanation 必须输出 before/after 诊断变化，例如：

建议在 1865 年插入缺轮 0。
编辑后：
B-like 问题段 5 → 1
传播模式消失
整体相关 0.736 → 0.809
边界附近 lag 回到 0

六、COFECHA 输出可以借鉴，但只能作为 hints
────────────────────────

新增一个可选解析模块，例如：

src/features/crossdating/diagnosis/cofechaHints.ts

它解析 COFECHA 类文本输出，不要求核心算法依赖它。如果用户没有提供 COFECHA 文本，算法仍然正常运行。

需要解析这些部分：

[A] Segment lag table

示例：
[A] Segment   High   -10 ... -1 +0 +1 ...
1815 1864   -1    ... .71* .15|-.15 ...
1825 1874   -1    ... .77*-.02|-.01 ...

解析字段：

type CofechaSegmentHint = {
startYear: number
endYear: number
highLag: number
correlationsByLag: Record<number, number>
starredLag: number | null
starredR: number | null
}

用途：

* 验证 segments.ts 算出的 bestLag 是否接近 COFECHA highLag。
* 如果多个 COFECHA segments highLag 同号，给 propagation confidence 加分。
* 不能直接输出编辑建议。

[B] Entire series / segment effect on correlation

示例：
Lower   1866< -.053   1865> -.035 ...
Higher  2009  .029 ...

解析字段：

type CofechaEffectHint = {
scope: "entire" | "segment"
segmentStartYear?: number
segmentEndYear?: number
direction: "lower" | "higher"
year: number
marker?: "<" | ">"
effect: number
}

用途：

* lower 年份作为候选可疑年份 evidence。
* 多个 segment 中重复出现的年份加权更高。
* 不直接决定插年或删年。

[C] Year-to-year changes diverging

示例：
1829 1830  -5.5 SD
1865 1866  -4.9 SD

解析字段：

type CofechaYearToYearHint = {
year1: number
year2: number
sd: number
}

用途：

* 对边界附近候选加分。
* 对 deleteFalseYear 和 insertMissingYear 都可作为局部异常证据。
* 不作为硬过滤。

[E] Outliers

示例：
1829 +4.0 SD; 1865 +4.3 SD; 1884 +3.7 SD

解析字段：

type CofechaOutlierHint = {
year: number
sd: number
}

用途：

* 对 candidateYear 附近加分。
* 不直接决定插删。

新增函数：

parseCofechaHints(text: string): CofechaHints
getCofechaEvidenceForYear(hints, year): number
getCofechaSegmentLagSupport(hints, segmentStart, segmentEnd, lag): number

COFECHA hints 进入评分时使用 cofechaHintEvidence，权重默认 0.8，不允许超过 propagation / actual evaluation 的权重。

补充修改：RDM.rwl 不只包含 RDM151 和 RDM192，测试必须遍历文件中的所有合格序列。RDM151 / RDM192 只能作为固定 smoke test / regression test，不得作为唯一测试对象。

────────────────────────
七、RDM.rwl fixture 测试策略改为全序列批量测试
────────────────────────

用户提供的 RDM.rwl 是一个已经定年好的 RWL 文件，里面包含多条 series。测试不能只针对 RDM151 和 RDM192。必须实现通用 fixture loader，并对所有合格序列批量构造 synthetic corruption cases。

RDM.rwl fixture 查找路径：

1. src/features/crossdating/diagnosis/**fixtures**/RDM.rwl
2. tests/fixtures/RDM.rwl
3. 项目根目录 RDM.rwl

如果 fixture 不存在：

* RDM fixture integration tests 可以 skip。
* parser unit tests、synthetic pure unit tests 不能 skip。

RWL parser 要求：

* 读取所有 seriesId。
* 返回 Record<string, SeriesValuesByYear>。
* 保留 0 宽度值，0 是缺轮占位，不是非法值。
* 只把 -9999 作为 stop marker。
* 支持每条 series 多行、跨 decade。
* 自动计算 startYear / endYear。
* 不硬编码任何 seriesId。
* 不硬编码任何年份范围。
* 测试中可以断言 RDM151 / RDM192 存在，但不能只测试它们。

新增 helper：

loadRdmFixture(): Record<string, RwlSeries>

type RwlSeries = {
id: string
startYear: number
endYear: number
valuesByYear: Map<number, number>
nonZeroCount: number
zeroCount: number
length: number
}

新增筛选函数：

getEligibleSeriesForSyntheticTests(seriesMap, options)

默认筛选条件：

* length >= 100
* nonZeroCount >= 80
* endYear - startYear + 1 >= 100
* 序列有足够 overlap 可用于 leave-one-out master
* 不要求没有 0；0 必须被保留，但构造 synthetic case 时避开已有 0 附近 ±2 年，避免真实缺轮干扰判断

新增分组：

eligibleLongSeries:

* length >= 150

eligibleMediumSeries:

* length 100–149

eligibleWithZeros:

* zeroCount > 0

eligibleWithoutManyZeros:

* zeroCount <= 3

测试时不要只取第一条。至少从 eligibleLongSeries 中选择多条，建议：

* 前 5 条
* 中间 5 条
* 最后 5 条
* 如果数量不足则全部使用

为避免测试过慢，可以设置：
MAX_RDM_SYNTHETIC_CASES = 12 或 16

但必须保证不是固定只测 RDM151 / RDM192。

────────────────────────
八、基于所有合格序列构建 leave-one-out master
────────────────────────

新增测试 helper：

buildLeaveOneOutMaster(seriesMap, targetId, options)

规则：

* master 不包含 target 自己。
* 使用所有与 target 有足够年份重叠的其他序列。
* 每条参考序列先走项目当前 reference signal / z-score / chronology 构建流程。
* 按年份构建平均 chronology。
* 如果项目已经有 dynamic COFECHA-pass reference，优先复用。
* 如果可用参考序列太少，该 target 的 integration case 跳过，但记录 skip reason。
* 测试中不能因为某一条序列参考不足导致整个测试失败。

默认要求：

* 至少 5 条参考序列参与 master。
* target 与 master overlap >= 80 年。
* 如果达不到，则跳过该 target 的 synthetic case。

新增返回：

type FixtureMasterBuildResult = {
targetId: string
referenceSeriesIds: string[]
masterValuesByYear: Map<number, number>
overlapYears: number[]
skipped?: boolean
skipReason?: string
}

────────────────────────
十、批量 synthetic missing-ring 测试
────────────────────────

新增 helper：

createEndAnchoredMissingRingCase(series, missingYear)

语义：

* 输入 correctly dated series。
* 固定 endYear 不变。
* 删除 missingYear 这一年的值。
* missingYear 以前的值整体向较新年份移动 1 年。
* 生成 corrupted target。
* expected operation = insertMissingYear at missingYear。

注意：
这是为了模拟“target 中缺少 missingYear 这一轮，但树皮端 endYear 正确”的情况。

选择 missingYear：

对每条 eligible target：

1. 从 target 与 master overlap 中选择候选年份。
2. 避开：

   * target startYear 附近 20 年
   * target endYear 附近 20 年
   * target 已有 0 年份附近 ±2 年
   * master 缺值年份
3. 优先选择 master 中较窄 / 较低 signal 的年份。
4. 如果没有 master signal，则选择 overlap 中部年份。
5. 对每条 target 构造 1 个 missing case。
6. 总 case 数限制为 MAX_RDM_SYNTHETIC_CASES。

测试期望：

对每个 case：

* diagnosis 能运行。
* 生成 insertMissingYear 候选。
* top 5 candidates 中至少一个 insertMissingYear 位于 missingYear ± 1。
* 若算法输出 strong candidate，则 top candidate 应位于 missingYear ± 1。
* 应用候选后重新诊断：

  * B-like count 减少，或
  * dominantLag 更接近 0，或
  * wholeSeriesR 不下降且 segment mean R 提升。
* 不要求每条真实噪声序列都 exact top-1 命中；但整体成功率必须达标。

批量成功率断言：

* attemptedMissingCases >= 5。
* missingTop5HitRate >= 0.70。
* missingTop1HitRate >= 0.40。
* 如果 fixture 中 eligible cases 不足，则测试输出 skip reason，不应假失败。

────────────────────────
十一、批量 synthetic false-ring 测试
────────────────────────

新增 helper：

createEndAnchoredFalseRingCase(series, falseYear, falseValue)

语义：

* 输入 correctly dated series。
* 固定 endYear 不变。
* 在 falseYear 处加入一个额外值。
* falseYear 以前的值整体向较老年份移动 1 年。
* 生成 corrupted target。
* expected operation = deleteFalseYear near falseYear。

falseValue 不能总是极端小值。至少实现三种模式：

1. average:
   falseValue = (left + right) / 2

2. moderate:
   falseValue = local median

3. splitLike:
   把原 falseYear 附近一个正常值拆成两个较小值，但总和接近原值

每个 case 随机性必须 deterministic，使用固定 seed。

选择 falseYear：

对每条 eligible target：

* 避开 start / end 附近 20 年。
* 避开已有 0 年份附近 ±2 年。
* 避开缺值年份。
* 优先选择局部信号清晰、master overlap 好的年份。
* 总 case 数限制为 MAX_RDM_SYNTHETIC_CASES。

测试期望：

对每个 case：

* diagnosis 能运行。
* 生成 deleteFalseYear 候选。
* top 5 candidates 中至少一个 deleteFalseYear 位于 falseYear ± 1。
* 不要求被删除值是极端小值。
* delete 候选必须通过 hard gate，不能只靠极端值证据。
* 应用候选后 propagation 减弱或消失，或 lagRecoveryScore > 0。

批量成功率断言：

* attemptedFalseCases >= 5。
* falseTop5HitRate >= 0.60。
* falseTop1HitRate >= 0.35。

────────────────────────
十二、批量 wholeSeriesMove 测试
────────────────────────

新增 helper：

createWholeSeriesMoveCase(series, lag)

语义：

* 保持 values 顺序不变。
* 将整条序列年份整体偏移 lag。
* 不插入 0。
* 不删除值。
* expected operation = wholeSeriesMove。

对 eligibleLongSeries 执行：

* lag = +1
* lag = -1
  根据测试耗时可只取部分 series。

期望：

* wholeSeriesMove 候选存在。
* wholeSeriesMove 排名应高于 insertMissingYear / deleteFalseYear。
* 不应把整条移动误判为单年插删 top-1。
* top wholeSeriesMove 的 lag 与真实 lag 一致。

批量成功率：

* attemptedWholeMoveCases >= 5。
* wholeMoveTop1HitRate >= 0.70。

十三、批量 partialRangeMove 测试
────────────────────────

新增 helper：

createPartialRangeMoveCase(series, boundaryYear, lag)

语义：

* 较新一侧保持正确。
* boundaryYear 以前的较老一侧整体偏移 lag。
* 不插入 0。
* 不删除值。
* expected operation = partialRangeMove。

选择 boundaryYear：

* 位于 target overlap 中部。
* 避开已有 0 附近。
* 两侧至少各有 50 年。

期望：

* partialRangeMove 候选存在。
* partialRangeMove 排名高于单个 insert/delete。
* boundary 在真实 boundaryYear ±2 年内。
* 应用候选后 B-like count 减少或 dominantLag 接近 0。

批量成功率：

* attemptedPartialMoveCases >= 5。
* partialMoveTop5HitRate >= 0.60。

九、end-anchored 编辑 helper 必须单独测试
────────────────────────

新增 helper 并测试：

applyEndAnchoredInsertMissingYear(valuesByYear, insertYear, value = 0)

规则：

* endYear 固定。
* insertYear 及其较新年份中，较新年份保持不动。

示例：

1865=C
1866=D

1863=原1864 B
1864=原1865 C
1865=0
1866=原1866 D
1867=原1867 E

这个测试必须存在，防止 1865 / 1866 off-by-one 错误。

applyEndAnchoredDeleteFalseYear(valuesByYear, deleteYear)

规则：

* endYear 固定。
* deleteYear 的 target 值被删除。
* deleteYear 以前的值整体向较新年份移动 1 年。
* deleteYear 以后的较新年份不动。

必须明确这两个 helper 仅用于候选模拟，最终真实应用仍调用 edit.ts 的正式编辑路径。
